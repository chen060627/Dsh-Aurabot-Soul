# Aurabot Soul 1.0 发布检查

下列驗證結果來自本次整理前的插件基線。

## 本次检查结果

- 完整测试共 1,394 项，1,390 项通过，0 项失败，4 项跳过。
- QQ、OneBot 模拟网关、人格与记忆隔离、连续消息、投递回执、归档、备份恢复、定时任务、媒体工具和权限的现有回归测试均执行。
- 新增了情绪误判、重复自述、过时情绪判断、WS 重连、草稿与实际投递内容、保存设置竞态，以及 B 站替代插件和自定义 DSH 资料目录的回归测试。
- dsh-bili-scroll 2.5.2 的前后端自检通过。真实 HTTP 处理器使用模拟的平台响应，验证生成二维码、查询状态、保存账号与 Aurabot 读取同一账号的接线。
- 使用真实 React DOM 验证了二维码显示、等待扫描、手机确认成功后的账号刷新和卸载清理。
- 生产依赖安装及 npm 封装清单检查通过。压缩包保留了上游许可与修改说明。

## B 站替代插件

随包整合完整的 dsh-bili-scroll 2.5.2 插件源码，并通过本地依赖与 bundle 声明加载。其扫码会话与本地账号凭据由该插件管理。Aurabot 继续通过兼容接线提供原来的看视频、字幕、评论、弹幕、截图与 QQ 分享。

本次集成调整了二维码的本机 JavaScript 绘制、登录请求超时、过期或被替换的二维码处理，以及凭据原子保存。扫码无需先安装 Python。使用替代插件自身的 MCP、转写等独立功能时，其设置页仍负责安装相应依赖。

新插件独立的定时刷视频和自动评论初始关闭，原有 Aurabot 功能按其设置运行。用户 QQ 会话通过原有工具与权限执行操作。原来手动保存的登录设置保留，新入口使用替代插件的扫码账号。

来源为 https://github.com/c1overzz/dsh-bili-scroll ，二维码编码器为 qrcode-generator 2.0.4。完整署名见 THIRD-PARTY-NOTICES.md。

## 测试范围的边界

本轮没有使用用户的真实 QQ 或哔哩哔哩账号，也没有在用户实际的 DSH 桌面环境中完成扫码确认。平台接口、风控、账号有效期、客户端版本和网络仍可能影响结果。二维码失效可以刷新，账号失效需要重新扫码。

4 项跳过项分别为 Windows TTS、Windows 安装位置与盘符检查，以及两个未安装旧版本源码的对照测试。固定配置升级测试已经执行。

浏览器进程受当前执行环境限制未能启动，扫码页面使用真实 React DOM 和模拟 HTTP 验证。没有完成完整浏览器的视觉与交互验收。

聊天表达仍受所选模型、人格与历史上下文影响。自动测试验证了状态和接线，不能证明每次生成的措辞都像真人，也不能证明所有环境下完全没有缺陷。

## 安装与发布

解压后，在 DSH 插件管理中添加「01 插件程序」文件夹，让 DSH 完成依赖安装，再重启 DSH。打开 Aurabot 的 B 站页面点击「手机扫码登录」，在手机端确认。详细使用说明见 使用说明_思考插话与情绪系统.md。

package.json 中的仓库和更新来源仍指向上游项目，尚未配置用户自己的发布仓库。发布为独立派生项目时，需要使用实际的包名和仓库地址。
